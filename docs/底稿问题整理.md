# 底稿问题整理说明

> 本项目只做一件事：**把「电子底稿编制 / 送审 / 复核」时要问的问题整理出来**。不做抽取、建图、判定管线。

## 三、问题为什么这样分

问题沿两条轴组织：

1. **按底稿编制与送审环节**：送审前置 → 管理类 → 综合类 → 操作类（资产基础法/收益法/市场法）→ 报告说明明细表 → 归档。
2. **按底稿类型/科目**：财务类科目问题直接落到《步骤及复核表》的逐条操作步骤（`步骤复核表.yaml`），主问题集只保留跨科目通用问题和重点科目特有问题。

每条问题含：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定编号（`Q-SR-001` 等），引用/勾选时不要改 |
| `ask` | 问题正文 |
| `check` | 判定要点 / 依据说明（可选） |

`步骤复核表.yaml` 中每个科目含 `subject / index（底稿索引号）/ step_count / variant_count / sources / steps[]`，`steps` 即该科目《步骤及复核表》「操作步骤与要求」列原文。

## 四、怎么用

1. **逐项勾选**：把 `底稿问题集.yaml` 按组渲染成清单（或直接读 YAML），对每项打「是 / 否 / 不适用」，`否` 即问题。
2. **定位底稿**：`index` 是底稿索引号（如 `C3-5` 应收账款），文件名应与核实表索引号一致，可直接定位。
3. **与送审表对应**：`send-review` 组对应「送审表（勾选）」的审核人四问（有没有？错在哪？缺什么？完整打勾）。
4. **与报告结构对照**：`report-errors` / `detail-errors` 是报告与明细表的低级错误清单，可作为出报告前的自检。

## 五、复现抽取

各科目步骤来自 `scripts/extract-step-tables.py`：

```bash
python3 scripts/extract-step-tables.py   # 依赖 xlrd / openpyxl / pyyaml
```

脚本逻辑：遍历操作类底稿全部 `.xls/.xlsx`，取表名含「步骤」的 sheet，抽取行首形如 `N、...` 的操作步骤，剔除表尾说明，按科目归并（同名多套取最全的一套），索引号取出现次数最多者（旧模板可能带过期索引号）。

## 六、已知边界

- 财务类底稿按 A类/B类/C类项目并存，科目相同、步骤以最全的一套入库；`variant_count > 1` 表示存在多套模板。
- 部分科目（如使用权资产、商誉、租赁负债）索引号在不同模板间有冲突，已按出现次数取众数，个别仍需人工确认。
- 步骤表的「是 / 不适用」勾选与复核人签字，是底稿合规的一部分，问题集只记录问题文本，不代替实际签字。
- 管理类 GL-4（聘请专家）、质控会记录等视项目情况适用。
