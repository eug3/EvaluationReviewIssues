## 三、底稿要提供哪些支撑

《资产评估档案》准则把工作底稿分为两类，这就是"底稿支撑"的全部来源：

| 类别 | 定义（archive-2018 §9） | 具体内容（§10–11） |
| --- | --- | --- |
| **管理类工作底稿** | 为受理、计划、控制和管理业务所形成 | 业务基本事项记录、委托合同、评估计划、重大问题处理记录、审核意见 |
| **操作类工作底稿** | 为现场调查、收集资料和评定估算所形成 | ①现场调查记录与资料（评估明细表、权属证明、历史/预测/财务/审计资料、承诺函、勘查/询问/函证记录）②收集的评估资料（市场调查与数据分析、询价记录、专家报告）③**评定估算过程记录（重要参数选取与形成过程、价值分析/计算/判断、结论形成过程、沟通记录）** |

报告附带的**评估说明、评估明细表、收益法底稿、市场法底稿**，都是上述三类底稿的载体。

**评估说明的法定内容**（国资指南 §35–38）：

- §36 评估说明使用范围声明
- §37 《企业关于进行资产评估有关事项的说明》7 项：委托人/被评估单位概况、经济行为、评估对象与范围、评估基准日、可能影响评估工作的重大事项、资产负债与未来经营收益预测、资料清单；须单位负责人签名盖章
- §38 《资产评估说明》4 项：**评估对象与评估范围说明、资产核实总体情况说明、评估技术说明、评估结论及分析**
- §43–44 收益法/市场法评估技术说明：宏观区域经济、行业、业务、资产财务分析与调整、方法运用过程

归纳为报告需要的**七类支撑**：

1. **程序与受理类**（管理类）：委托合同、计划、基本事项、审核意见
2. **现场调查与核实类**：盘点、勘查、询问、函证、账表实相符记录
3. **权属与法律类**：权属证明、经济行为批准文件、营业执照、承诺函
4. **财务与审计类**：专项审计报告、财务报表、报表调整
5. **取价与数据类**：市场调查、询价、统计资料、可比公司/交易案例数据
6. **测算与参数类**：评估明细表（账面/评估/增减值）、收益法预测与 FCFF、折现率、市场法价值比率与分成率
7. **结论与沟通类**：结果汇总、方法比较、结论确定依据、与委托人沟通记录

## 七、判定规则（缺支撑时怎么判）

沿用 `schema/verdict.yaml`：

- `supported`：底稿有明确证据且与报告一致（如汇总表金额=报告结论金额）
- `contradicted`：底稿有证据但冲突（如明细表合计≠说明披露、两处金额不一致）
- `missing`：按追问检索后底稿无对应（如报告写了特别事项但无核查记录）
- `insufficient`：有部分证据但不完整（如只有结论没有测算过程、参数无来源）
- `not_applicable`：不适用（如未采用的方法）

`schema/report_section.yaml` 中每条支撑都带 `if_absent`，给 S4 判定提供默认结论与严重度。

## 八、与问题集/schema 的衔接

- 每个报告章节的 `claim_types` 决定 S1 抽取出的命题归类（见 `schema/claim.yaml`）
- 每条底稿支撑的 `question_group` 指向 `questions/review_checklist.yaml` 的追问组（见 `schema/report_section.yaml`）
- `workpaper_support` 的 `where` 是 S3 取证时的检索域提示（评估说明/明细表/收益法/市场法/附件）

一句话：**报告十三项每一句实质性表述，都要能在七类底稿里找到落点；找不到就是 `missing`，冲突就是 `contradicted`，只有结论没有过程就是 `insufficient`。**
